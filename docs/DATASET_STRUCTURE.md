# 数据集逻辑结构

## 1. Scenario

`Scenario` 表示相对稳定的线路与通信环境，包括：

- 线路空间范围；
- AP 数量、位置、间距、高度和天线参数；
- OBM 布局和列车长度；
- 载波频率；
- 路径损耗、阴影和多径参数域；
- 接收机报告参数；
- 参数来源类型及适用边界。

它不是“所有可能线路”的穷举，而是有依据的有限场景族。

## 2. Run

`Run` 表示一趟从起点到终点的完整运行，包括：

- 时间—位置—速度轨迹；
- 一次冻结的随机传播世界；
- 健康或故障状态；
- 故障目标、严重度及参数；
- 生成器版本、配置哈希和随机种子；
- 配对健康运行标识；
- 官方数据划分。

同一个 Scenario 下可以有多条 Run，用于覆盖不同速度轨迹、随机实现和故障状态。

## 3. Sample

`Sample` 是从 Run 中围绕目标 AP 截取的诊断窗口。它保存：

- `sample_id` 和目标 AP；
- 上下文窗口范围；
- 健康/故障标签；
- 故障目标和严重度；
- 对应观测文件；
- 可选的质量标志。

同一 Run 可以产生多个 Sample。

## 4. Observations

`Observations` 不是第四级编号，而是 Sample 内部的逐点长表。每一行对应一个报告时刻下某个 AP—OBM 候选链路。多 AP、双 OBM 场景中，同一时刻可以有多行。

原始长表是权威表示；补零+掩码或重采样矩阵属于派生的模型输入，不应覆盖原始数据。

## 5. 防止数据泄漏

- 不逐行随机切分；
- 同一 Run 的所有 Sample 放在同一集合；
- 配对健康/故障 Run 放在同一集合；
- 若要测试场景泛化，应按 Scenario 分组；
- 所有官方划分随版本冻结并发布。
